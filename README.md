## About

<div align="center">
<img src="https://img.shields.io/badge/-ABOUT-7C3AED?style=for-the-badge&labelColor=0D1117" alt="About" />
</div>

I am an entry-level data analyst finishing a B.Sc. in Information Technology in Mumbai. I build end-to-end analytics projects that start with messy data and end with a decision a business can act on.

- **Analytics engineering:** I clean data in PostgreSQL, define KPIs as SQL views, and test ideas in Python before anything reaches a dashboard.
- **Statistics and ML:** I apply hypothesis testing, regression, K-Means clustering, RFM, and funnel analysis, and I report results that are not significant.
- **Full-pipeline delivery:** Each project goes from raw data to cleaning, analysis, a Power BI dashboard, and a written recommendation.
- **LLM-assisted analytics:** I built a Gemini-powered text-to-SQL assistant that lets non-technical users query a shipment database in plain English.
- **Product mindset:** I start from the business question and the decision it supports, then pick the tool.

**Open To**

- Entry-level Data Analyst and Business Analyst roles
- Analytics internships and trainee programs
- Collaboration on open data and analytics projects

<details open>
<summary><b>Supply Chain Vendor and Delivery Performance Analysis</b></summary>
<br/>

End-to-end analytics pipeline that finds where shipments run late and which factors actually drive freight cost, with a natural-language query layer on top.

| | |
|:--|:--|
| **Stack** | PostgreSQL, Python (pandas, scikit-learn, SciPy, Statsmodels), Power BI, Gemini API |
| **Scale** | 6,025 shipment records, 8 SQL KPI views |
| **Performance** | Raw table, cleaned table, and KPI views follow a medallion-style flow |
| **Security** | Synthetic dataset modeled on a public schema, so no sensitive data is used |
| **Impact** | Delays are spread widely: 296 of 561 vendor-route combinations account for 80% of late shipments, so no single fix solves it |
| **Repository** | [Supply-Chain-Shipment-Pricing-And-Delivery-Risk-Analysis](https://github.com/yashmonde24/Supply-Chain-Shipment-Pricing-And-Delivery-Risk-Analysis) |

I cleaned the data in PostgreSQL, defined delivery KPIs as SQL views, and ran vendor segmentation, Pareto root-cause analysis, chi-square and ANOVA tests, and a freight-cost regression in Python. Shipping mode showed no significant effect on on-time rate (p = 0.12) or freight cost (p = 0.14). The finding rules out an easy explanation and points the recommendation at vendor and route segments. A Gemini-powered text-to-SQL assistant lets non-technical users query the data in plain English.

</details>
